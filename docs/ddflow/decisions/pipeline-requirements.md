## The questions and the accepted defaults

Accepted as written on 2026-10-13 (recommended defaults, verbatim from the task body):

QUESTIONS AND RECOMMENDED DEFAULTS
1. Field or kind? DEFAULT: one optional `pipeline` field (a table) on the existing guidance record (rule or decision); no new kind, no new store, no new config file. Rejected: a pipeline-rule kind (a second engine beside the record surface), and growing [gates] with per-glob tables (invisible to search, brief and RAG, outside the waiver/deviation engine).
2. What may an effect say? DEFAULT: require=[gate...] (with optional after=), allow_na=[gate...] with a reason class, forbid_skip=[gate...], order=[[a,b]...], kinds=[...] (item kinds it covers), define={gate table} for a project-specific gate backed by a declared command (executable: approved by digest, inert until approved, B-gap-command-trust). Gate DEFINITIONS stay in [gate.*]; the record only names ids.
3. Strength. DEFAULT: reuse enforcement x override from B-goal-decide. MUST (block, waive|none): the gate cannot be dropped, skipped or made N/A; only a person's waiver (<=90 days, scoped to globs) lifts it. SHOULD (warn, deviate): the gate is added as recommended; an agent records an item-scoped deviation with a reason, answered before complete. MAY (advisory): listed in gate status, never refused. A deviation never lifts a MUST.
4. What does 'scope matches' read? DEFAULT: the existing Scope (globs, categories, gates) plus kinds and tags; globs are matched against the item's declared globs at claim and against the ACTUAL diff (changed_paths) at gate status and complete; a requirement that matches either one applies (additions can only grow); an allow_na needs the diff to MISS (declared globs alone never grant N/A: bug B-na-required-gate).
5. Resolution time. DEFAULT: at claim, recorded as a pipeline.resolved event (resolved gate list with the source of each, digest of rule and config inputs, engine version); re-resolved at gate status/complete: gates may be ADDED mid-flight (the agent is told which rule added it), never removed without a recorded N/A or waiver. A rule edit never silently changes an in-flight item.
6. Agent powers. DEFAULT: additive and free: add a gate to this item (reason required, event, shown in review and metrics, capped by [pipeline].max_added = 3 per item, then a note); N/A of a non-required gate not covered by a MUST: allowed with reason class and evidence; ANY weakening (remove a gate from a pipeline or kind, N/A or skip of a required/MUST gate, lower a reviewer/evidence requirement, edit [gates].required, demote a record's strength) becomes a pending proposal only a person clears (builds on B-org-agent-guard). Agent-authored requirement records start status proposed, additive effects only, active after the operator accepts (like decisions).
7. The four invariants. DEFAULT: shipped as an org-style floor that no project record can weaken: unavailable never passes (already structural), every pipeline gate carries an outcome (gates.require_outcome), a cross-family reviewer on authored tasks, a regression test for a bug. They become policy-tier knobs (B-org-agent-guard) and the resolver refuses a requirement whose effect would remove them.
8. Precedence. DEFAULT: the P-goals order (org floor > project MUST > accepted decision > principle > preference); additions COLLECT (union); removals use strictest-wins (any MUST require beats any allow_na); an order cycle is a doctor error and the base order stands. Not 'first match' (DMN first-hit hides rules).
9. Preview. DEFAULT: ddflow workflow preview (--kind, --globs, --tags) and workflow diff (this change vs current, over open items) on CLI and MCP; an enforcement tier 'evaluate' that resolves and reports but adds nothing (GitHub ruleset evaluate idea, Gatekeeper dryrun) for the first N days of a new requirement.
10. Versioning and skew. DEFAULT: unknown `pipeline` keys in a record are carried, not dropped; an engine that does not know the field refuses to complete an item that a block-level requirement covers (fail closed), warns for warn-level.
11. Sprawl brake. DEFAULT: [pipeline].max_added = 3, a requirement that adds a gate must name a gate with a command or an evidence contract (no pure-prose extra gates), requirements that fired on zero items in 60 days are listed for review (B-dec-review), and a rule count cap shared with [rules].
