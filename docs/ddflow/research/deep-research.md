## 4. Ranked shortlist (max 10)

Ranking = value / (cost x risk), weighted by reuse of planned machinery.

### 1. Descriptor `research` facts (data only)
Design: add to the descriptor-v2 schema a `[research]` section (owner amendment, since v2 reserves names): `search_tools` (names, e.g. WebSearch/WebFetch, google_web_search/web_fetch, codex web_search), `search_modes` (cached/live/off), `search_enable` (argv/config key to turn it on headlessly), `search_limit` (e.g. 200 per interactive session), `subagents_parallel` (bool), `deep = none|api:<adapter>`, `mcp_search_ok`, plus the usual three-valued absent=NOT VERIFIED and `[verified]` date/source. Fill for claude, codex, gemini first from §2; the rest stay NOT VERIFIED and are probed through the shared facts table.
Cost: small (schema + 3 TOMLs + loader tests). Risk: low; facts rot (mitigate with verified date and `ddflow doctor` staleness). Reuse: harness registry loader, probe/facts table, D-everything-configurable. Needs: P-agent-parity.descriptor-v2.

### 2. Search-capability and consent policy knob (`[research.web]`)
Design: per-project policy: web allowed / cached only / off; allowed-domain list; whether a question may leave the machine to a third-party research service (consent record per provider); the claim prompt for a research item states the policy and the harness is started with the matching flags (`--allowedTools`, `--search`, `--permission-prompts none`). Enforced where the harness supports it, otherwise recorded as unenforced (never silently pass).
Cost: small-medium. Risk: low. Reuse: P-safeguards, autonomy section, allowlist rule already in P-research-flows ("nothing runs a verifier not on the operator's allowlist"). Needs: 1, P-safeguards.

### 3. Delegated deep-research lane (API adapter, background)
Design: a research stage kind `delegate`: adapters for OpenAI Responses deep research, Gemini Interactions deep research (with `collaborative_planning`, so the committed RF-plan IS the approved plan), and Perplexity Agent API. Flow: consent check (2) -> cost preview and budget (`max_tool_calls`/`max_uses`) -> start background job -> poll or webhook via the existing job machinery -> store the raw report + cited URLs as an UNVERIFIED claim set (trust=agent, grade asserted) -> mandatory audit (5) and verification (4) before it can rise on the ladder. A delegated report never becomes `supported` or `verified` by its own say-so.
Cost: medium-large; real money per run (tens of cents to many dollars: UNVERIFIED per-vendor), minutes to tens of minutes. Risk: vendor churn (model ids deprecated while this report was being written), prompt injection through the vendor's browsing, privacy (question and any attached context leave the machine). Reuse: jobs (job add), cost envelope, descriptor/adapter registry pattern, RF-template stage list, reviewer-endpoint credential handling. Needs: 1, 2, RF-template, P-safeguards.envelope, RF-audit.

### 4. Research panel with agreement scoring and disagreement resolution
Design: reuse B-pi-review-panel at the claim level: N independent answerers from distinct families get the same research question (and optionally the same fetched evidence pack) WITHOUT seeing each other (CoVe-style independence); claims normalised to atomic form; agreement = distinct families asserting an equivalent claim (family-weighted, not raw counts, because same-family agreement is correlated: CAPA); outcome per claim: agreed (>=2 families) / contested / singleton. Contested claims go to a resolution stage: fetch primary sources for the contested point only, then a tie-break by evidence (not by vote), recorded as the ladder step. Two families default, three optional, knobs `min_families`, `agreement_floor`, `resolve = evidence|operator`.
Cost: 2-3x tokens for the panelled stages only (restrict to claims that are load-bearing or flagged); medium code (extends panel merge by similarity). Risk: models agree wrongly (shared training data); mitigated by requiring a source, not an opinion, to promote to supported. Reuse: B-pi-review-panel (merge, found_by, quorum), reviewer pool + independence rule, B-rw-verify, RF-confidence. Needs: B-pi-review-panel, B-rw-verify, RF-confidence.

### 5. Mechanical citation audit extended to claim-level support (SAFE/ReportBench style)
Design: RF-audit already checks URL resolves/quote present. Add the second half: per claim, the cited span is retrieved and a judge (other family, small model) answers entails / contradicts / unrelated; report two numbers, citation validity (resolves + quote present) and statement support (entailed). Thresholds as data; gate fails below floor; unresolvable = unavailable. Include a "cited but never fetched in this run" check using the harness transcript or the API's tool-call log (OpenAI/Claude/Codex expose search items), because deep-research products can cite URLs they never visited (UNVERIFIED claim; an open question listed at emergentmind.com for OpenAI).
Cost: small-medium; cheap tokens (SAFE is >20x cheaper than human rating). Risk: low. Reuse: B-rw-sources fetch helper, RF-audit gate, B-rw-verify entailment pack. Needs: B-rw-sources, RF-audit.

### 6. Provenance record for every research input
Design: one `research.trace` record per search/fetch/delegated call: who (agent/vendor/model), query, tool, time, URL list, content hash, cost, cap hit. Sourced from `codex exec --json` web_search items, Claude stream-json tool_use/result blocks (including `parent_tool_use_id` for subagents, headless doc), API `server_tool_use` blocks, Gemini thinking summaries. Claims link to trace ids. This is the evidence for "did the agent actually read it" and makes cost per question visible. Records follow the record contract (RC1-RC12).
Cost: medium (parsers per harness, feeds the transcripts/telemetry descriptor section). Risk: parser drift per harness version. Reuse: descriptor `[telemetry]`, job records, claim sources. Needs: P-agent-parity.descriptor-v2, B-rw-sources.

### 7. Research critic role (report-level, rubric-based) plus gate
Design: a `research_critic` lens/gate distinct from per-claim verification: sees the question, the plan, the evidence table and the report, NOT the author's reasoning; other family; fixed rubric: coverage gaps vs plan, claims without evidence rows, source-quality (primary vs SEO), confirmation bias (any disconfirming search attempted?), contradictions unaddressed, scope creep; outputs findings in the usual triage format with severity, plus an Anthropic-style 0-1 score per axis recorded for trend (RF-eval). One adversarial round, not open-ended debate.
Cost: small (a lens template + gate def + rubric file); one extra other-family call per report. Risk: self-preference if same family (prevented by the existing floor); rubric gaming. Reuse: B-pi-review-lens, `critic` gate machinery, triage, RF-roles skeptic (this IS the report-level counterpart). Needs: B-pi-review-lens, RF-roles.

### 8. Effort-scaling and budget rules for research stages
Design: encode Anthropic's heuristics as template data: question complexity class (fact / comparison / open survey) -> default number of parallel searchers, tool calls each, and token budget; cost preview shows it (GV-workflows) before start; `max_uses`/`max_tool_calls`/`--max-budget-usd` passed through to the harness or API as the enforcement point where one exists. Searcher briefs must carry objective, output format, tools, boundaries (the "vague task" failure mode).
Cost: small. Risk: wrong defaults (mitigated: knobs, RF-eval). Reuse: RF-stop, P-safeguards.envelope, GV-workflows, subagent defaults. Needs: RF-template, GV-workflows.

### 9. MCP search companion bundle
Design: treat Exa / Tavily / Brave / Firecrawl / GPT-Researcher MCP as optional companions (like roborev, context7): `ddflow companions` lists them with what installing each runs, operator opt-in, injected into harnesses whose descriptor lacks native search (cursor, cline, roo, kilo, aider, opencode...). Keys via env, never in events. Fence tool output as untrusted data.
Cost: small. Risk: third-party data flow, key handling; recorded unavailable if declined. Reuse: companions registry, `[mcp]` writer, existing never-install-without-asking rule. Needs: 1, 2.

### 10. Report eval harness with planted traps and rubric scoring
Design: extend RF-eval: fixtures with a known-answer question set (small public or synthetic), planted fake citation, planted source that contradicts, SEO-vs-primary choice; score each shipped workflow on citation validity, statement support, coverage; run per release to catch regressions when vendor tools or models change. Optional import of ReportBench/DeepResearch Bench tasks as external fixtures (UNVERIFIED licensing).
Cost: medium; recurring spend. Risk: judge drift. Reuse: RF-eval, idea 5 scorers. Needs: RF-eval, 5, 7.

## 5. Rejected ideas

| Idea | Why not |
|---|---|
| Unlimited multi-round LLM debate between models | 15x-style token cost, same-family consensus is correlated (CAPA), debate gains shown mostly on reasoning benchmarks, not source-grounded research; one adversarial round plus evidence-based tie-break is enough. |
| Majority vote of N same-family samples as "verification" | Self-consistency raises answer stability, not truth where errors are shared; violates the spirit of the other-family rule. Allowed only as a cheap noise filter below `supported`. |
| Trusting a vendor deep-research report as `supported` or `verified` | Reports contain statement and citation hallucination (ReportBench); cap at `asserted` until audited (idea 5) and independently verified. |
| Building ddflow's own search crawler / index | Duplicates MCP servers and native tools; violates reuse-the-core. |
| Hard-coding model ids / endpoints of OpenAI/Gemini/Perplexity | The sources fetched here show deprecations (o3/o4-mini deep research, Sonar) within a year; ids must be data with a verified date. |
| Always-on delegated deep research for every research item | Cost and privacy; cheap native search covers most items. Make it opt-in per workflow with a preview. |
| Importing STORM / GPT-Researcher / Open Deep Research as the engine | They are alternative orchestrators (one archived 2026-08-21); ddflow's value is gating, records and independence, not another planner. Use as design references and, for GPT-Researcher, as an optional MCP server. |
| LLM-judge-only citation validation | Loses to mechanical resolve/quote checks which are deterministic and free; judge only for entailment after those pass. |
| A separate confidence scale for research panels | RF-confidence says no parallel grading scheme; agreement maps onto `supported`. |
