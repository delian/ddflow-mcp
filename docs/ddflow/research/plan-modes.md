# ddflow roadmap as the plan for native agent plan modes

Research of 2026-10-16. Read-only: no ddflow state or repo file was changed. F = verified from a source I fetched or read; I = inference; U = could not verify.

Key point: plan modes are conversation states, not APIs; only Claude Code, Gemini CLI and Kiro give an outside tool a documented handle. Execution must stay in ddflow; native todos are a mirror.

### Multi-agent, subagents, worktrees (c)
- Claude Code: subagents, agent teams, `SendMessage`, cross-session messaging; background agents; worktrees via `--worktree` (F, tools-reference). Teammate task status "can lag" (from ddflow's own R-gaps-survey). Plan mode applies per session; a subagent inherits restrictions (I).
- Gemini: research subagents allowed read-only in plan mode (F). Cursor: subagents and cloud/background agents (PM-cursor-cloud covers the API, public beta). Kiro: waves run concurrently (F). Copilot: custom agents, handoffs (F). Codex: multi-agent features (P-fleet). opencode: subagents `@general/@explore/@scout` (F).
- Nobody coordinates **file-level exclusion** between agents; that is ddflow's lease/glob layer (F, ddflow). Native plans therefore assume one agent owns the whole plan. I: this is the real value ddflow adds.

### Known limits
Cursor plan-file portability bug; Codex `update_plan` default off; Claude plan mode is not enforced when bypass permissions are available interactively (F); Gemini headless auto-approves plan transitions (F); Windsurf plan lives outside the repo (F).

## 3. Design options

Shared definition: a **plan slice** = the tasks selected by a query (`--label wave:0`, `--phase P`, or "the ready set now"), with id, title, needs, globs, acceptance, priority, and the exact `claim` command, rendered from the log. Read-only, derived, hash-stamped with the event-log position so staleness is detectable.

### (i) Export a slice in the agent's native format
- Minimal v1: `ddflow plan export [--label wave:0|--phase P|--ready] --format md|checklist|json` printing the slice. Wire it as an MCP **prompt** (`plan_slice` with args `label`, `format`) and as slash command/custom command text via `ddflow adopt`/onboard templates: `.claude/commands`, `.cursor/commands`, `.gemini/commands`, `.github/prompts`, `.opencode/commands`, Windsurf workflows (all documented carriers above). The command text says: "Plan only. Do not edit files. Produce a plan that is exactly this slice's tasks; for each, confirm globs and order."
- Optional v2: write the file where the agent expects it (Gemini `general.plan.directory`, Kiro `.kiro/specs/ddflow-<label>/tasks.md`, Copilot `.copilot/plans/`, Claude `plansDirectory`). Only Gemini, Kiro and Claude have documented, repo-local paths; Cursor and Windsurf plans live in home dirs (F) so they get prompt text, not a file.
- Risk: a written plan file is a second source of truth the day it is edited. Mitigation: header says generated, stamped hash; `plan import` rejects a stale hash.
- Configurable: knobs `plan.export.format`, `plan.export.dir.<agent>`, `plan.slice.default` (rule r-everything-configurable).

### (ii) Import the accepted plan as ddflow tasks/needs
- Minimal v1: agent's approved plan is a markdown/TOML block; `ddflow plan check -` (exists) then `ddflow plan apply -` (TODO) files tasks in one transaction, labelled `plan:<session>`. The plan-mode agent has no claim, so *it must not write the queue itself*; the operator runs apply, or a gated step does. In Claude Code the `ExitPlanMode` PermissionRequest hook (F) is the natural trigger: the hook calls `plan check` on the plan text and **denies the exit with the findings** (overlaps, missing acceptance) so the agent revises before it is allowed to execute. I: this is the strongest native fit, no tool needed. Equivalent for Gemini via policy engine on `exit_plan_mode` (F existence, behaviour I).
- Risk: LLM invents ids/globs; planning "outside its lease/globs". Mitigation: `plan check` is mechanical; imports file `plan`-labelled tasks `proposed` (not ready) until the operator confirms; plan-review round with a cross-family reviewer.
- Configurable: `plan.import.autoapply` (off), `plan.import.state` (proposed), max tasks per import.

### (iii) Execute in ddflow's loop, mirror progress into the native todo list
- Minimal v1: no mirroring tooling at all. The command text from (i) tells the agent: "execute by `ddflow_claim` per task; after each ddflow call, update your todo list from `ddflow_next`/`ddflow_gate_status`". ddflow stays authoritative; the todo is regenerated each turn.
- v2: read-only `plan status --format checklist` (markdown checkboxes, same ids) so the agent can paste it into TodoWrite/TaskUpdate/update_plan/tasks.md. A hook-based push is feasible only where the agent has a post-tool hook (Claude, Cursor, Gemini; F) and even then the agent's todo list is model-called, not writable by a hook (I), so v2 means a `SessionStart`/`stop` hook that *injects* the checklist as context, not writes it. Kiro is the exception: ddflow could update `tasks.md` checkboxes directly (I, U whether Kiro re-reads on change).
- Risk: drift (todo says done, gate says not). Mitigation: only ddflow events change state; todo text says "mirror, derived at <log position>"; Codex `update_plan` left default-off in ddflow-generated config to avoid competing surfaces (secondary source).
- A plan-approved agent must still `claim`; claim refuses a lease overlapping another lane, which is the answer to "agent plans/edits outside its globs".

### (iv) MCP prompts/resources instead of tools
- Recommended carrier for (i) and half of (iii): prompts `plan_slice`, `plan_execute` (arguments: label/phase/ready), and resources `ddflow://plan/<label>` (markdown) and `ddflow://plan/<label>.json`. Zero tools/list bytes. Client support for MCP prompts is uneven (Claude Code surfaces them as slash commands F via ddflow docs, others U) and resources are mostly read by the user or by explicit selection, not automatically (I). Hence also ship the file/command forms.
- `ddflow_prompts` already exists as a tool; extend that rather than add tools. Importing needs a write path, so (ii) stays CLI + hook, or a single optional argument on an existing tool (precedent: R6a721b0684 added `for_agent` within 56 bytes).

### Recommended combination
v1 = (i) markdown/prompt export + (iv) as MCP prompt + (ii) via CLI `plan check/apply` and the Claude `ExitPlanMode` hook gate + (iii) as instruction text only. All read-only on the queue except `plan apply`.

## 4. Task proposals for phase `P-plan-modes`

Priority bands: A = do first, B = after A, C = optional/probe. All CLI/MCP changes follow D-everything-configurable and the tools/list budget rule (CLI-only or prompt/resource first; I did not check the ids' final globs, so the filer must run `plan check`).

- **PL-decide** (A): Ask the operator the plan-mode choices (section 5) and file the decision. Needs: none. Body: record whether the queue or the agent file is the plan, whether import may auto-apply, whether a plan-mode hook may block `ExitPlanMode`, which agents are in scope.
- **PL-probe** (A): Probe, per agent, the facts I could not verify: Claude Task store on disk and `plansDirectory` behaviour with `-p`; Codex plan artifact and exec/app-server plan event; Cursor CLI plan mode and where saved plans land; Copilot coding-agent (github.com) plan gate; Kiro re-read of edited `tasks.md`; Windsurf `brain/` writability; which clients render MCP prompts. Record results in the descriptors with source and date. Needs: P-agent-parity.descriptor-v2, CP-verify-facts (pattern).
- **PL-slice** (A): `core` plan-slice projection and `ddflow plan export [--label|--phase|--ready] --format md|checklist|json`: pure, from the log; includes needs, globs, acceptance, claim command, log-position stamp, wave number from `core.schedule.waves`. CLI-only declaration (`tool=""`) with a reason. Needs: B-gap-plan-lint, LB-waves (for `--label wave:N`; until it lands, `--wave N` computed on the fly).
- **PL-prompts** (A): MCP prompts `plan_slice` and `plan_execute` plus resources `ddflow://plan/...`, templates overridable via `ddflow prompts eject`; no new tools. Needs: PL-slice, DX-agent-brief.
- **PL-apply** (A): finish `plan apply` (atomic, files as proposed, labelled `plan:<id>`, stale-hash refusal) and the add-time warning from B-gap-plan-lint's REMAINING list; cross-check with the task owner so it is not filed twice. Needs: B-gap-plan-lint, LB-engine.
- **PL-exit-hook** (B): Claude Code `PermissionRequest` hook on `ExitPlanMode`, written by adopt with consent: runs `plan check` on the plan file, denies with the findings or allows (never auto-applies). Gemini equivalent via the policy engine if PL-probe confirms. Needs: PL-apply, P-agent-parity.permissions, P-agent-parity.descriptor-v2.
- **PL-native-export** (B): per-agent writers from descriptor data: command/prompt files (`.claude/commands`, `.cursor/commands`, `.gemini/commands`, `.github/prompts`, `.opencode/commands`, Windsurf workflow), Gemini `general.plan.directory`, Kiro `.kiro/specs/ddflow-<label>/{requirements,design,tasks}.md`; each with manifest and revert like other adopt writers. Needs: PL-prompts, PL-probe, P-ai-import.
- **PL-mirror** (B): `ddflow plan status --format checklist` and a session-start/stop hook injection of the checklist so the agent's todo list is regenerated, never edited by ddflow; Kiro `tasks.md` checkbox write-back behind a knob if PL-probe shows it is safe. Needs: PL-slice, P-agent-parity.continuation.
- **PL-lane-plan** (B): lane-aware slice: for N lanes, group the ready set by non-overlapping globs and render one slice and brief per lane (the "plan for a team" a coordinator writes by hand today). Needs: PL-slice, DX-dispatch-plan, B-gap-lanes (done).
- **PL-acp-plan** (C): map ACP session plan updates (ACP defines a plan update type; U, check the spec version) into ddflow events and show them in the lane ledger; also PM-jules `requirePlanApproval` as an approval route. Needs: AC-events, PM-jules.
- **PL-acceptance** (A, last): with fakes, an agent plans a wave:0 slice, the exit hook refuses a plan with an overlapping glob pair, the revised plan applies, execution claims and completes through the loop, and the mirrored checklist matches `ddflow status`. Needs: PL-exit-hook, PL-mirror, PL-lane-plan.

## 5. Open questions for the operator

1. Source of truth: confirm "queue wins always; an agent plan is a proposal until `plan apply`". May an approved plan auto-apply, or always `proposed`?
2. Should a plan-mode hook be allowed to *block* `ExitPlanMode` (strong, Claude-only) or only warn?
3. Which agents are in scope for native writers first? I suggest Claude Code, Gemini CLI, Kiro (documented repo-local plan paths), then Cursor/Codex/Copilot prompts.
4. Is it acceptable for ddflow to write into an agent's plan directory (`.gemini/plans`, `.kiro/specs`) or only emit text? (D-agent-parity limits what ddflow installs without consent.)
5. Slice selector: wave labels (needs LB-waves, still open) vs phase vs ready set; is a `plan:<session>` label namespace acceptable?
6. Unattended modes: Gemini auto-approves plan transitions and Claude plan mode can be bypassed, so in headless runs the plan gate is not a human gate. Should the human gate then be `plan apply` approval inside ddflow (approvals engine in P-shared-engines)?
7. Is the remainder of B-gap-plan-lint (apply, warning, review round) already tracked elsewhere? It shows `done` while its body lists unfinished work.
8. Should mirrored todos exist at all, given the reported Codex hedging between two planners? Option: off by default for Codex.
