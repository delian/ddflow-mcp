# dsh probe: facts from running it

Task `DSH-facts`, phase `P-dsh-fit`. Follows `docs/ddflow/research/dsh.md` (source-read) and `docs/ddflow/decisions/dsh.md` (operator: "Tier 1 live smoke now", 2026-10-22). Fixtures are in `tests/fixtures/dsh_probe/` (paths, uuids and the home directory replaced by `<SCRATCH>`, `session-<UUID>`, `<HOME>`).

## How it was run

- Installed `@deepseek-ai/dsh@0.2.1-rc.2` and `@deepseek-ai/dsh-hooks-claude-code@0.2.1-rc.2` with `npm install --ignore-scripts` into a scratch directory outside the repo; downloaded files treated as untrusted (never executed outside `dsh`). Scratch `HOME` and `DSH_HOME`, so no real profile, key or session store was touched.
- Model backend: a local stdlib Python stub on 127.0.0.1 speaking OpenAI Chat Completions (no real key; `STUB_API_KEY=fake-not-a-key`). `DSH_TELEMETRY_MODE=DISABLED` was set for the runs (see Telemetry).
- Node: the user's `/home/delian/.nix-profile/bin/node` is **v24.21.0** (the operator's confirmed install); `/usr/bin/node` is v24.22.0. **dsh failed on the nix v24.21.0** (`host preparation failed: node-addon-require-builtin unsupported: Unsupported/no-getter (x64 sysv getter is not a recognized this->field accessor)`) and worked on `/usr/bin/node` v24.22.0, run as the user (no sudo). So "Node >= 22.19" is necessary but not sufficient: dsh patches Node internals through `node-addon-native-custom-loader`, and a given Node build can be refused. `--version`, `--help` and `--dump-default-config` work on both.
- Kernel 6.8, Linux x64. Landlock sandbox: every bash result carries `landlock-run: partial enforcement (older Landlock ABI)` on stderr.

## New facts the source read did not have

- **Telemetry is not Desktop-only.** The base composition mounts `session-telemetry-otel`, mode `FEEDBACK_ONLY` by default, exporter `https://dsh-otel-collector.deepseeksvc.com/v1/logs` (overridable by `DSH_TELEMETRY_OTLP_URL`, mode by `DSH_TELEMETRY_MODE`). Its README: records are exported only after an explicit feedback action (`/feedback`, a rating); `DISABLED` constructs no transport. A headless lane has no feedback action, so nothing should leave by this path, but that is a statement, not a captured negative. dsh.md and the operator's decision 5 said telemetry is Desktop-only; the premise was wrong and the decision ("record, not toggle") still stands: the probe set `DSH_TELEMETRY_MODE=DISABLED` in its own scratch environment only.
- **MCP protocol** (`mcp_handshake.ndjson` is a reduced recording: the `tools/list` result is replaced by `tools_count`, `tool_names` and `tools_json_chars`, and `instructions` are cut, to keep the fixture small; the raw 115k-char reply is not committed): dsh speaks the stateless 2026-07-28 revision: no `initialize`; the first message is `server/discover` with `_meta` carrying `io.modelcontextprotocol/protocolVersion` `2026-07-28`, `clientInfo` `{name: dsh-mcp-client, version: 0.0.1}` and empty `clientCapabilities`, then `tools/list` with the same `_meta`. ddflow's stdio server answered both (it lists `supportedVersions` back to 2024-11-05). dsh declares **no** client capabilities in the handshake; `tools/list_changed` handling was not exercised (ddflow advertises `listChanged: false`).
- **Overlay mechanics**: a `--patch` file is a YAML list. An entry with an `id` **overrides an existing row and replaces its whole `config`** (nothing merges). A **new** row needs `- insert: [ {id, name, config} ]`. An id-only entry that targets nothing prints `patch: entry "x" not found` and boots anyway. Plugin `name` resolves from the **profile directory** (`$DSH_HOME/profiles/<p>/`), not from the launch directory.
- **Hooks bridge install**: `npm view` dist-tags: `latest` = 0.0.1-rc.5 (stale), `next` = 0.2.1-rc.2. The 0.0.1-rc.5 package is disabled by dsh's compatibility gate (`disabling profile plugin row ... incompatible with dsh 0.2.1-rc.2`, agent still runs with no hooks, only a stderr warning) and, mixed with 0.2.1 dsh, the first tool call died with `Cannot read properties of undefined (reading 'prepare')`. The version matching dsh (`@0.2.1-rc.2`, dist-tag `next`) works. A bare package name in the overlay failed to import (resolved from the profile dir); an **absolute path to `.../dsh-hooks-claude-code/lib/index.js`** in `name` worked. So the bridge can be mounted from a repo overlay without editing `$DSH_HOME`, but only if ddflow installs a version-matched copy somewhere itself (the alternative, `dsh plugin add`, writes into the profile and needs per-agent consent under decision 2).
- **Hook child environment**: the hook process inherits the launching shell's environment and gets `CLAUDE_PROJECT_DIR` from the bridge. Under a Claude Code parent the `CLAUDE_*` and `CLAUDECODE` variables leak into dsh's hooks; hook-side Claude detection by environment is unreliable for dsh.
- **Approval with no answerer** (headless, `workspace-write` + `ask`): a write outside the workspace is refused by the sandbox (`[sandbox: file access denied under workspace-write mode]`, with an escalation hint); retrying with `sandbox_permissions: danger-full-access` returns `sandbox escalation ... requires approval, but no approval channel is available`. Both are tool errors the model sees; the process still exits **0**. In-workspace `bash echo` ran without any ask. File not created outside; confirmed.
- **Exit codes and events**: success, a hook-denied tool and a sandbox-denied tool all exit 0 with a `final` event; a missing key exits 1 with `dsh: MISSING_CREDENTIAL: ...` on stderr and a `turn_end` event whose reason is `error`, `final.text` empty. NDJSON event types seen: `session`, `status` (phases `turn_start`, `step_start`, `step_end`, `turn_end`), `text`, `tool_call`, `tool_result` (status `completed` or `error`), `final`.
- **ACP**: `initialize` returns `protocolVersion 1`, `agentInfo {deepseek-harness-acp, 0.0.1}`, `mcpCapabilities {http: true}` (no `sse`), prompt capabilities all false (no image, audio, embedded context), session capabilities `close`, `list`, `resume`, `authMethods []`. Nothing beyond `initialize` was driven.
- A session title request is sent to the model as a second, tool-less request on every run that reaches the model (an extra model call per session, `session-title-llm`; not made when the credential is missing).

## Claims of dsh.md

Confirmed by running: headless `--json` event set and exit 0/1; credentials from the environment in headless; `ask` with no answerer fails closed; MCP tools registered before turn 1 and named `mcp__<server>__<tool>`; `clientInfo` `dsh-mcp-client` `0.0.1`; hook payload field names, `transcript_path` empty; hook exit 2 blocks; the bridge fails open on a bad plugin.
Refuted or corrected: "Product telemetry is Desktop-only" (a session-telemetry exporter exists in the base composition, feedback-gated); "install the bridge as a package named in the overlay" (needs a path or a profile install, and the right version); "Node >= 22.19 is enough" (the nix v24.21.0 build is refused).
