## Findings

1. A user-selectable threshold or window at launch exists on Claude, Codex, Gemini, Kimi, Qwen, Goose, Kilo, OpenCode, Grok, Cline (mode only) and dsh (profile); none on Copilot, Cursor (CLI), Roo (IDE), Amp, Windsurf, Aider (history cap only).
2. Only Claude Code, Goose and Kimi take the window by environment variable; Codex by `-c`; Kilo/OpenCode by inline config env; the others need a file in a lane-private config dir. This is why the descriptor proposal uses a setter table (env, argv, file), not one env-name field.
3. Units differ: tokens (Claude, Codex, Goose limit, Kimi reserve), ratio 0-1 (Gemini, Kimi, Qwen, Goose), percent (Kilo, Grok, Roo, Claude override). The advisor's single threshold (CC-Q4: lanes 150/250/350 K) is converted per agent through its declared window; where the window is unknown the setter is not applied (`unavailable`).
4. Claude's PCT override can only lower the window; Codex's scope setting changes what the limit counts; Goose triggers on the smaller of ratio and token limit; Kimi on whichever trigger fires first. Applying one ddflow number to all of them needs the per-agent semantics above, not a copy.
5. Long-context extension is a model choice nearly everywhere (Claude `[1m]`, Cursor extended context, Gemini tiers); it is a plan-dependent paid feature on Claude (credits) and Cursor (legacy Max Mode). Selecting a larger model at launch is a routing decision (D-model-routing: only at safe points), not a window knob.
6. Implementation lives in `ATF-descriptor-fields` (fields) and `ATF-launch-env` (applying the setter); this task is the research table that feeds them and CC-inventory.
